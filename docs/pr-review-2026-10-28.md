## 추가 PR 검수 — 2026-10-29

### #10: undefined 허용이 일부 props에서 빠졌다

[`exactOptionalPropertyTypes`를 켠 변경](https://github.com/heogeon0/aui/pull/10)은 소비 프로젝트의 조건부 props를 지원하는 데 필요하다. 그러나 `Button.loading`, `Stack.gap`, `Card.tone`, `Input.inputSize`, `ToastProvider.duration`, `ChoiceOption.disabled`, `BreadcrumbItem.href`에는 `undefined`가 빠졌다. 예를 들어 `<Button loading={undefined}>저장</Button>`은 여전히 TS2375로 실패한다.

PR의 기존 타입 검사는 통과했지만, 위 7개 사용 예제를 추가하면 모두 실패했다. 빠진 공개 props를 보완하고 `className?: never` 같은 스타일 제한은 유지한다. PR #7의 새 API와 현재 로컬에 추가한 `Badge.size`·`Select.selectionTitle` 등도 반영 시 함께 확인한다.

### #11: Drawer 높이와 footer 배치가 깨진다

[`size`의 CSS](https://github.com/heogeon0/aui/blob/6e83973e92618e1672a021dc9205a731700f507d/packages/design-system/src/styles.css#L915)가 모바일에만 제한되지 않았다. 1440×1000 화면에서 오른쪽 Drawer의 높이가 `half`는 500px, `tall`은 850px이 된다. 기본 `auto`는 1000px이다. 높이 선택은 아래에서 열릴 때만 적용하고, 데스크톱에서는 화면 높이를 채우도록 수정한다.

또한 [본문](https://github.com/heogeon0/aui/blob/6e83973e92618e1672a021dc9205a731700f507d/packages/design-system/src/styles.css#L872)이 남은 높이를 채우지 않는다. `tall`에서 검색 결과가 한 개로 줄면 footer가 본문 바로 뒤로 올라오고 그 아래에 빈 공간이 생긴다. 390×844 화면에서 footer와 Drawer 바닥 사이가 약 500px 벌어졌다. 높이를 지정한 Drawer에서는 본문이 남은 공간을 채우고, 긴 내용만 스크롤되도록 수정한다.

검색창을 고정하는 `header` 슬롯은 범용성이 있다. 우선 이 슬롯과 검색 결과에 필요한 높이 선택을 중심으로 반영하고, drag·snap·키보드 정책까지 확장하지 않는다. 긴 목록뿐 아니라 빈 결과·짧은 결과·footer·데스크톱 전환도 검사한다.

### #9: 문서 배경을 되돌리는 테스트가 필요하다

[`applyToDocument`](https://github.com/heogeon0/aui/pull/9)를 기본 꺼짐으로 제공하는 방향은 적절하다. 적용 범위는 가장 바깥 provider의 문서 배경·color-scheme으로 한정한다.

현재 테스트는 `page.goto()`로 다른 Story를 연 뒤 속성이 없어졌는지만 확인한다. 새 문서는 원래 속성이 없으므로 provider의 cleanup이 실행되는지 증명하지 못한다. 같은 페이지에서 옵션을 끄거나 provider를 제거해 기존 배경색·color-scheme이 복원되는지 검사해야 한다.

## 반영한 Drawer 기능 — 2026-10-29

사용자가 선택한 Drawer의 `header`·`size`만 기존 패키지에 반영했다. 제목 아래 검색창·필터를 고정하고, 하단 높이는 auto·half·tall·full 중에서 고른다. 옆에서 열리는 Drawer는 화면 높이를 채우며 짧은 결과에서도 footer는 바닥에 붙는다. visualViewport가 줄면 고정 영역과 목록 한 줄에 필요한 최소 높이를 확보한다.

Storybook `Layout/Drawer`에 검색·선택 예제와 높이 Controls를 추가하고, 타입 검사와 AI 문서의 props·예제를 갱신했다. 로컬 Storybook은 http://localhost:6006/?path=/story/layout-drawer--search 에서 확인한다.

`pnpm check`를 통과했다. 단위 테스트 19개와 E2E 194개가 통과했고 모바일에 해당하지 않는 검사 4개는 제외했다. 두 Theme의 라이트·다크를 모바일·웹에서 확인하고, Docs에서도 검색·선택을 조작했다. visualViewport 축소는 테스트에서 높이와 위치를 바꿔 확인했다. WebKit의 최소 높이 계산 차이를 보완했고, 기존 Toast 검사에서 44px이 43.99994px로 측정되던 부동소수점 오차도 보정했다.

## ListItem 두 크기와 Table 모서리 — 2026-10-29

ListItem의 기본 sm은 제목·설명을 가로 한 줄에 놓는 44px 행이다. 긴 문구는 말줄임한다. lg는 제목 아래에 설명을 두고 최소 64px에서 내용에 따라 늘어난다. native button의 type·disabled·이벤트·ref·ARIA를 유지하며, 임의 스타일·다른 size·selected는 공개하지 않는다. 기본 예제·크기 비교·앞뒤 콘텐츠 예제와 AI 문서를 추가했다.

타입·ESLint·단위 테스트 21개·AI 문서 생성 검사를 통과했다. 전체 E2E에서 205개가 통과했고, 기존 Modal 검사 한 건은 애니메이션 종료 전에 위치를 읽어 실패했다. 종료를 기다리도록 보완한 뒤 세 브라우저에서 해당 검사를 통과했다. 새 ListItem 검사 12개와 독립 패키지 설치·타입·SSR 검증도 통과했다.
